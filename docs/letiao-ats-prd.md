## 二、 产品概述

### 2.1 业务背景

当前企业的招聘管理主要依赖 Excel 和微信，简历散落在各大招聘平台和本地文件夹，难以集中管理；HR 与用人经理在推简、面试环节的沟通成本极高，容易遗漏重要信息；且历史沉淀的未录用简历无法被二次盘活。急需一套纯供企业内部员工使用的招聘流转系统来规范作业流程。

### 2.2 产品目标

1. **简历统一归集与解析**：将分散的外部简历统一归集、智能解析，形成企业专属的标准化人才库。
2. **规范化内部协同**：在线化流转“推荐-面试-拟录用”全流程，告别微信/邮件传简历带来的信息磨损。
3. **触达自动化与协同**：系统集成邮件/短信模板，由系统代发通知并支持简单确认回执，降低HR的机械性工作量。
4. **数据可视化沉淀**：提供核心的招聘漏斗与效能数据，基于全局视图量化招聘成果与业务瓶颈。
5. **数据隐私与合规管控**：由于脱离个人微信/Excel办公，需在系统中建立严格的RBAC权限，确保简历数据的安全流转与隔离。

### 2.3 目标用户与角色

| 角色                          | 核心诉求                                                                         |
| :---------------------------- | :------------------------------------------------------------------------------- |
| **HR / 招聘专员**             | 职位发布、录入/解析简历、推动候选人流程、安排面试日程、发送通知、发起Offer审批。 |
| **HRD / 招聘负责人**          | 拥有全局数据视图，监控各岗位招聘漏斗、各环节流转效率与卡点，统筹资源与招聘进展。 |
| **用人经理 (Hiring Manager)** | 在线评估HR推荐过来的简历（能够快捷操作通过/淘汰）、给出最终录用决策。            |
| **面试官 (Interviewer)**      | 接收面试提醒日程、在线查看候选人简历并填写结构化面试评价。                       |
| **系统管理员**                | 组织架构/账号维护、角色权限配置、审批流设置、邮件/短信模板管理。                 |

## 三、 整体产品架构图 (抽象描述)

- **前端展示层**：HR管理后台（PC Web端）、业务协同端（PC/移动协同办公APP嵌入，如企微/钉钉，仅供用人经理/面试官使用）。
- **核心业务层**：职位管理、简历解析与查重、拖拽式流程看板（Kanban）、面试日历调度、Offer审批流、企业人才库。
- **触达与通知层**：邮件/短信网关（向候选人单向发送提醒）、内部IM消息网关（提醒内部员工待办事项）。
- **数据与外部集成层**：外部招聘渠道API、第三方电子签章API、视频会议API（如腾讯会议）、内部核心E-HR系统。

## 四、 核心功能需求详细说明 (Functional Requirements)

### 4.1 职位管理 (Job Management)

- **职位创建与维护**：定义职位基础信息（JD、薪资范围、城市等）及内部协同信息（指定负责HR、所属部门）。
- **外部渠道发布**：支持将职位同步一键发布至已绑定的外部招聘平台（如BOSS直聘、前程无忧等，需视渠道API开放程度而定）。
- **职位启停控制**：支持岗位的开启、暂停、关闭，关闭后的职位不再接受新简历关联。

### 4.2 简历获取与解析 (Resume Sourcing & Parsing)

- **主推简历聚合方案（邮件转发）**：由于核心三方招聘平台API常常面临极为严格的限制，MVP阶段主推系统分配专属接收邮箱（如 `cv@letiao.com`）。HR设置招聘平台将投递转发至此箱，系统自动解析邮件正文及附件入库。
- **手动录入与AI解析**：HR可单份/批量上传本地简历文件（PDF/Word/JPG），系统利用OCR与NLP技术自动提取核心字段生成“标准电子简历”。
- **查重机制与简历归属保护期**：系统基于“姓名+手机号”或“姓名+邮箱”强校验。系统必须具备保护及防撞单逻辑：
  - **强冲突（活跃流转中）**：如候选人正在 A 岗位进行中，拦截 B 岗位 HR 的强行录入或提示业务冲突，建议优先判定录入归属顺序进行串行处理。
  - **弱冲突（人才库闲置）**：当候选人处于已淘汰淘汰且已过保护期（如半年），允许 B 岗位 HR 再次向新职位投递该候选人并自动汇总历史时间线。

### 4.3 招聘流程看板 (Pipeline Management)

- **自定义流程与批量操作**：提供经典环节底盘（初筛 -> 用人部门复筛 -> 一面 -> 二面 -> **背景调查** -> Offer -> 待入职）。适配不同类型岗位，应支持业务跳过冗余流程。作为效能工具，必须在看板和列表模式下允许进行**批量状态转移/批量淘汰**动作。
- **内部推简与敏捷反馈**：
  - HR针对初筛简历推荐后，系统推送内部消息给用人经理（依托企微/钉钉等通道）。
  - **IM消息卡片“即达即办”**：在消息卡片层直达展示简历摘要，并**附设“通过/待定/淘汰”动作集成按钮**，避免跳转登录导致流转停滞。
- **异常状态手动兜底**：鉴于不存在C端交互入口，HR必须可以轻松通过快捷弹窗进行异常节点的标记终止（如面试爽约）与状态流转覆盖。
- **淘汰归档追溯**：在操作任何深浅层级的“淘汰”动作时，必须点选明确的业务“淘汰动机/原因”，方便库数据分层留底被复用检索。

### 4.4 面试管理 (Interview Management)

- **内部企业日历协同**：在与所用办公套件打通的前提下，安排面试时可直观比对面试官日程（企微日历等）空闲状态。
- **闭环面试邀约（带H5回执）**：系统向外发送面试邀约邮件和短信。为弥补候选人反馈黑盒，在发送的**短信/邮件中附带一个轻量级的H5确认链接**。候选人点击“确认参加”或“申请调期”即在 ATS 后台自动回传变更简历状态，大幅削弱 HR 电话随访和核对确认的纯人力成本。
- **面试评价闭环**：面试官收到提醒，在线查看脱敏简历并填写结构化面评，面评时间线记录永久追溯并在流转时清晰展示。

### 4.5 Offer与入职管理 (Offer & Onboarding)

- **Offer内部审批与HC预警**：HR发起Offer跟交流动作，在内部流程中要能够提供该岗位的**定编量（Headcount）使用余量预警**，使得业务负责人能在流程当中权衡超编等风险防范。
- **Offer自动化下发与回执签收**：
  - 审批结束自动生成防伪 PDF 后系统代发邀约信（内含确认回执链接验证）。
  - 亦可考虑直接打通具备法律效力的实名电子签署模块（如e签宝），以保障签发留痕合规。
- **入职交接流**：候选人接受 Offer 并完成背调后，将其基本信息一键推入内部 E-HR 系统的“待入职”名单中（如后续产生拒Offer亦需同步废止退回操作）。

### 4.6 企业人才库与盘活 (Talent Pool & Nurture)

- **统一存储与人才夹（Projects）**：除统一底表外，支持HR自由创建个人的“人才储备夹/项目组”，将检索到的具有特定潜力的简历分类收藏。
- **复合搜索能力**：作为数据盘活核心，支持复合搜索（如搜索“Java” + “5年经验” + “淘汰原因不是技术不符”），便于进行高精度的人才回溯搜索体验保障。
- **人才保护期与公私海**：把控业务释放规则（如：HR私有跟进超过15天未实质推进推进），强制释放入公海；对于“归属保护期”内的人才，严格把控同业转移权限。
- **长效跟进Timeline**：任何处理动作、手动记录“跟进背景与笔记”都按照时间线结构化组合，形成长效的人才跟进资产底盘。

## 五、 非功能需求 (Non-Functional Requirements)

### 5.1 权限与安全体系 (Security & Access Control)

- **RBAC权限模型**：
  - HR端：仅能看到自己负责职位的候选人数据；HRD可拥有全局视图。
  - 用人部门端：只能查看本部门相关职位的推荐简历；普通面试官仅能看到分配给自己的候选人简历，且无导出权限。
- **数据脱敏**：默认屏蔽或掩码候选人的敏感信息（身份证号、期望薪资等），仅特定权限的HR可见。
- **防泄漏机制**：简历预览界面强制添加查看人员工号的全局水印。

### 5.2 触达配置 (Notification Configuration)

- **模板管理**：提供邮件和短信模板的可视化配置，支持插入变量（如 `{CandidateName}`, `{InterviewTime}`, `{PositionName}`）。
- **消息网关配置**：提供与企业微信/钉钉/飞书的集成配置界面，实现内部消息通知的畅通。

### 5.3 性能与合规需求

- 简历解析速度要求：单份简历上传至解析完成不超过 3 秒，解析字段准确率需达到 90% 以上。
- 由于未直接面对候选人收集隐私，系统录入需符合合规要求，支持一键删除/销毁指定候选人所有数据，以应对 PIPL（个人信息保护法）要求。

## 六、 演进路线规划 (Roadmap)

考虑到系统去除了较重的外链端和内推端，实施路径可以更加敏捷：

- **Phase 1：跑通核心骨干 (MVP，第1-2个月)**
  - **核心功能**：简历上传与解析查重、职位管理、基本的拖拽看板（初筛-面试-发Offer）、内部通知推送、面评记录。
  - **目标**：让HR彻底放弃Excel跟进表，实现业务流全部线上留痕。
- **Phase 2：自动化与协同深化 (第3-4个月)**
  - **核心功能**：招聘平台邮件代收抓取解析（或API直连录入）、面试日历冲突检测、系统直发邮件/短信含回执链接、电子Offer与内部审批流。
  - **目标**：提升协同效率，减少HR复制粘贴和手动发送沟通的琐碎消耗。
- **Phase 3：资产盘活与报表 (第5-6个月)**
  - **核心功能**：全面启用人才库（标签、公私海）、招聘漏斗数据大屏、团队效能报表、核心数据对接E-HR。
  - **目标**：实现数据驱动的招聘复盘和人才二次激活。

## 七、 提示（给体验与架构设计的重点把控项）

在您的系统落地中，请特别留意以下提升工作体感的交互特性：

1. **全局搜索（Global Search）前置**：HR在日常跟办跨平台、接听业务电话等碎片化场景中随时需要查人。顶部导航栏务必驻防随时待发搜索的全局模糊定位器，以便随时弹出人选履历。
2. **极简操作路径与批量操作**：因为是单端密集使用的管理工具，批量操作属必要保障（覆盖批量推简、批量通过等动作），避免反人性的枯燥点击。
3. **IM协同流流转轻盈化（卡片按钮操纵）**：向非专业系统人员（例如业务方）送达推简和审批，在消息体内自带通过/淘汰审批动作组件按钮，实现“即达即办”，无需二次拉端。
4. **统一时间胶囊轴重构背景**：完整的候选人 Timeline 时间线档案记录全域动态事件：包含了系统代发的邀约与H5回执以及HR手工注记备考，以防止业务传承和人员异动造成的信息真空。
